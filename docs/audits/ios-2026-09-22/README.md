# iOS 稳定性检查与修复 · 2026-09-22

本轮在工作区现有未提交修改之上检查了缓存恢复、数据模式切换、券商连接、CSV 导入、分析师和盈利历史卡片。保留已有改动；没有改交易计算公式或券商导入的数据口径。

## 修复

| 问题及触发条件 | 修复结果 | 代码 |
|---|---|---|
| 冷启动命中首页缓存时，只恢复持仓/图表，没有恢复已实现盈亏；切换数据来源时会残留上一来源的结果 | 缓存恢复按其账本及账户范围重建盈亏和缺口数；清空/重置同步清理。重置失败保留原显示结果 | `APIClient.swift` |
| Trading 212 读取中切换 Live/Demo 或凭证，旧响应被当前表单环境标记 | 固定每次请求的环境和凭证，请求期间禁用表单；缓存仅在完整且配置一致时复用 | `Trading212View.swift` |
| Trading 212 关闭弹窗后，晚到的请求仍可能导入并启动历史重试；旧请求可能结束新请求状态 | 页面拥有可取消的任务，迟到响应在导入前被拦截，旧任务无法清理新任务。已开始的本机保存可以完成，不做隐式回滚 | `Trading212View.swift` |
| CSV 部分行解析失败但整体成功，完成页不显示解析器的警告；仅含表头也可点击导入 | 完成页完整列出跳过行的原因；无数据行时禁用导入；导入中禁止重新选文件和重复启动；大字号下交易数量改为上下排列，避免英文单词挤断 | `CSVImportView.swift`、双语资源 |
| 分析师快照长期缓存首次请求时的股价，后来仍显示为“当前报价” | 评级、目标价和抓取时间保留，当前报价每次取最新持仓价格；无有效 USD 报价时显示缺失，不退回旧价 | `AnalystConsensusView.swift` |
| 分析师/盈利历史卡片快速收起再展开，已取消旧请求的清理会结束新请求加载状态 | 以请求标识约束加载状态、结果和错误发布，只有最新请求可更新卡片 | `AnalystConsensusView.swift`、`EarningsHistoryView.swift` |
