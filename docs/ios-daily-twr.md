# iOS 本地每日 TWR

## 首页账户资产（2026-09-13）

个人账户首页 `portfolioChart` 已切到同一重建引擎，首页不请求基准行情。
资产线为持仓加现金，蓝线为真实累计净入金（可以为负）。字段 `ChartPoint.cost`
因兼容绘图结构暂保留旧名，`PortfolioChartResponse.accountNAV` 存在时明确表示
此字段是净入金，不能作为证券成本使用。主页不再拼接即时股票市值作为今日账户净值。

区间金额为 `期末资产 - 期初资产 - 区间净现金流`；区间百分比为链式净值比值的
TWR，并显式标注。预设时间范围取首个可见日之前的估值作为期初；双指测量按所选
两个日终估值比较。不再拿净入金当收益率分母，也支持全额出金和只持有现金的账户。

首屏临时数据、缓存缺失和账本失败时不再展示股票快照充当账户总资产；显示不可用及
缺失原因，持仓列表仍显示自己的股票市值。纯缓存读取不会触发网络，现金-only USD
账本可以完全离线重建。Demo/公开披露维持各自来源标识，不把模拟资料当真实流水。

首页信息按钮说明日级重建、股息到账日和现金尚未对账的限制。Performance 中另一个
“当前持仓贡献”模型图仍有其原本的模型含义，并不等于这个真实账户资产图。

## 缺少资金流水时按交易推算（2026-09-13）

多数导入来源只有交易，没有现金分录：Trading 212 同步、Moomoo、IBKR、手动添加，
以及不带 Total 列的 CSV。原先只要有一笔缺现金，整个账户历史就不可用。现在只对这些
账户按下面三条推算重建（`ImpliedFunding.swift`），有完整资金流水的账户仍用真实分录：

- 缺现金的买卖，按「股数 × 成交价」、以成交币种推算现金；缺金额的现金类流水
  （入金、股息等）不计入。
- 某账户某币种某天收盘时现金为负，差额视为当天外部入金。
- 交易记录解释不了的持仓（历史被截断、证券转入、只有持仓没有交易），在最早有价格的
  那天（只有持仓时取券商给的开仓日之后）按收盘价转入，同时记等额入金。

每条推算都按市值入金，不会凭空产生收益。首页口径说明和收益页都会显示
「资金流水不完整」的说明。

单条异常流水不再让整个账户不可用，每种情况按市价做一个假设，并列进
设置 → 本机数据 → 数据问题：

- 缺成交价（常见于并购换股，如 CYBR）：按当天收盘价估值，没有就取前后 10 天内最近的收盘价。
- 读不懂的流水类型：跳过，持仓由上面的转入/转出规则与当前账户对齐。
- 重建出比当前多的持仓（换股、转出而没有卖出记录）：在最后一个收盘日按收盘价转出，记等额出金。
- 完全没有历史行情的证券：不计入账户历史，其余照常。
- 以上之后引擎仍失败（行情长时间缺口、缺汇率等）：对全部账户按推算重建，行情可沿用最多 21 天；
  再失败才退回按当前持仓回推市值的旧图，并在数据问题里写明原因。

## 现金流镜像共享账本（2026-09-13）

三种收益视图现在共用一次真实账户重建。`comparison` 不再加载首页成本路径；
`cashFlowMatchedBenchmark` / `cashFlowAdjustedPortfolio` 两个成本估算函数已删除。
无账本的快照回退返回 unavailable，没有估算曲线或旧日期的“最新”收益。

`AccountMWRLedger` 同时保留逐日入金和出金总额，不能从当日净额反推二者。
现金流镜像展示：`剩余资产（含现金） + 累计出金`，单位 USD；配套百分比为
`(剩余资产 + 累计出金 - 累计入金) / 累计入金`，是简单累计盈亏比例。
同日入金 100、出金 50 必须分别累计，不能只把净入金 50 作为分母新增。

基准以相同真实外部净流量在当日可用收盘总收益价格模拟，假设可买卖碎股、没有额外
交易费用。实际买卖和保留在账户内的收入不产生基准资金流。无法支付同额出金或资金
发生日没有可用行情时，从该处起基准结果不可用；不截零，不向未来价格挪动资金流，
不把旧的有效数值当作当前结果。报价最多跨四个自然日休市延用。

这些规则提高了账户与基准的可比性；日内执行、完整交易所日历、账户现金对账和
当前尚未适配的流水类型仍是明确限制，不宣称实际账户已经核准。

## MWR 共享账本（2026-09-13）

Performance 的 MWR 现复用同一次重建的每日外部净现金流和**含现金的全部净值**。
股票买卖、账户内股息与费用不会成为外部入出金。`AccountMWRLedger` 保存可审计的
日期、现金流和终值，供本机按区间重新计算；不依赖 Core。

MWR 输出所选期间的日期加权内部收益率，**非年化 XIRR**。切换范围时使用范围前的
账户净值作为期初投入；期初净值已经含有当天流水，不能再次加上该日入金。
双指测量也针对所测区间重新求解，不使用两点累计 MWR 相减。

基准使用相同日期和金额的真实外部现金流，以同日可用收盘总收益价格模拟进出。
基准资产不足以支付出金时，其后结果不可用；不将负份额截断后继续宣称等额出金。
该基准时点仍是日级约定，不代表实际日内执行。

资金账本失败时，MWR 和 TWR 一起报告数据缺口。离线的持仓快照/成本路径不再提供
估算 MWR。现金流镜像随后也已切换为该账本。现金未与券商余额对账、费用净额不明、
换汇和公司行动适配等现有限制同样适用于 MWR；不能把测试通过视为私人账户已核准。

验证包括真实资金账本到 MWR 的串联、闲置现金、卖出、区间期初入金去重、基准无法
支付出金、期间/年化区分、字段缺失，以及既有 MWR 求解器回归测试。

计算入口：`LocalMarketDataClient.accountTimeWeightedSeries`。纯 Foundation 引擎：
`DailyTimeWeightedReturn`。Performance 的 TWR 使用该入口，数据不足时显示原因。
当前权重模型不再作为账户 TWR 的回退。

## 口径与输入

- 起点为零现金、零持仓，要求从首次入金开始的完整流水。没有完整流水时，
  不能从今天持仓倒推出未知期初资产。本版尚无期初资产录入界面。
- 按账户和币种保存有符号 `Decimal` 现金分录；实际买卖改变数量和现金。
- 入金视为日初，出金视为日末：`factor = (期末净值 + 出金) / (上日净值 + 入金)`。
  日收益因子连乘。日内时点属于约定，并非已观察到的现金流时点估值。
- 股息按到账日计入、费用从现金扣除。因此是到账日、费用后的重建日收益；
  不声称符合含除息日应收股息的 GIPS 完整总收益口径。
- 已卖出证券也请求历史价格。逐日估值包含全部现金；负现金、负数量、缺价格、
  缺汇率、重复 ID、未知流水类型都阻止输出收益。
- 持仓与当前账户按账户/证券核对。现金快照尚未接入，页面明确提示现金未对账。
- 引擎可配对同日同币种的内部转账；App 导入层尚未自动识别转账或换汇的两侧，
  这些记录会被保留并阻止不完整结果。证券转账、并购和期初快照适配尚未完成。

## CSV 与兼容性

旧的 `LocalTransactionRecord` 可继续读取；新增可选 `cashPostings`。
旧记录缺失现金分录时不会按数量乘成交价补造资金流。

支持资金类型 Deposit、Withdrawal、Dividend、Interest、Fee、Tax 及 Buy/Sell。
资金行不需要 ticker/数量/价格。金额优先使用以下明确净现金列：

```
Action,Time,Ticker,No. of shares,Price / share,Currency (Price / share),Net cash amount,Cash currency
Deposit,2026-01-01,,,,,1000,USD
Market buy,2026-01-02,AAPL,1,100,USD,-101,USD
```

`Net cash amount` 是最终账户现金增减，已包含费用和税费，支出为负。
没有明确净现金列时，仅对无费用/税费列金额的行读取 `Total` + `Currency (Total)`，
按 action 确定方向。带费用的 Total 是否已扣费无法统一推断，因此留空现金分录，
请求明确净额。不得直接把费用重复加到已含费 Total 上。

无法解析的记录使该次导入的现金分录整体失效，避免跳过错误后仍宣称账本完整。
普通券商订单 API 的自动入出金同步、费用适配和现金对账不是本次已完成能力。

## 行情

行情通过 iPhone 公共行情请求获取，本地缓存；私人资金账本不发送给行情服务。
Yahoo 的 split-adjusted close 按响应拆股事件还原为当时价格，数量在拆股日按比例
调整。使用交易所时区确定行情日期；不使用含股息复权价为真实数量估值。
汇率使用历史值，不使用今天汇率重估全部历史。已观察价格和汇率最多延用四个
自然日以跨越短休市，超过即缺失；这不是完整的逐交易所日历覆盖验证。

Core 仅为开发时核查来源；iOS 不需要连接 Core 或 T7。

独立引擎测试（不启动 App）：

```sh
swiftc CatfolioIOS/CatfolioIOS/DailyTimeWeightedReturn.swift scripts/check_daily_twr.swift -o /tmp/catfolio-check-daily-twr
/tmp/catfolio-check-daily-twr
```

16 个案例：存取款、链式复合、清仓、分红、费用、拆股/反向拆股、内部转账、汇率、
以及缺资金/缺行情/重复/负持仓等失败路径。

可选第二个命令的参数为 Core `daily-query-verification.json` 的路径。
检查文件中价格为 USD / UNADJUSTED，再用一股的合成账本逐日对照 `close / initialClose`。
2026-09-13 已对一年扩展审核文件的 **88 个回读估值样本**核查通过；不是全库覆盖，
不是私人账户对账，也不等同于 Yahoo 与 Core 两个来源的逐点价格核对。

`LocalPortfolioEngineTests` 包含资金 CSV、费用歧义、未知动作、坏行、旧数据兼容与
现金字段序列化测试。完整编译和模拟器测试需使用 Xcode。
