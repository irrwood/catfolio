# 加载和缓存

更新日期：2026-09-15。范围：Catfolio 原生 iOS 客户端的业务数据和页面展示；不包括登录令牌等凭据有效期。

本文记录当前实际实现，不表示所有页面已经遵循统一的缓存策略。最近的“保留展示内容、再次打开直接显示”修改主要覆盖个股页。

## 基本概念

| 概念 | 当前含义 |
|---|---|
| 页面加载 | 读取缓存、整理图表、恢复状态或调用服务；不一定联网 |
| 缓存有效期 | 允许复用结果而不请求更新的时间，不是到点自动执行的定时器 |
| 内存缓存 | App 当前进程内可直接使用的数据；进程结束后消失 |
| 磁盘缓存 | 可跨 App 重启保留的数据；读取、解码、整理仍需时间 |
| 缓存过期 | 通常表示下次相关任务执行时需要检查更新，不代表立即删除旧数据 |
| 手动刷新 | 由具体页面或卡片决定范围，不存在一个自动强刷全 App 的统一入口 |

除交易记录页的同步轮询等明确例外外，下面的 5 分钟、12 小时、24 小时等期限，都在进入、展开、刷新或其他相关业务任务触发时检查。当前不是持续推送实时行情的机制。

## 图表首次动画与加载占位

- `ChartAppearanceHistory` 在当前 App 进程内记录已经展示过真实数据的图表，不随返回、关闭详情、Tab 切换或视图重建重置。进程退出后记录重置，下次启动可再播放一次。
- 使用稳定的图表 ID；个股价格包含证券和报价币种，研究小折线、期权墙、盈利历史按证券区分。主题、语言、日期和时间范围不作为首次动画的 ID。
- 只在真实图表出现时登记，创建视图、等待请求或失败状态不会消耗首次动画机会。
- 第一次展示折线可播放 0.45 秒入场；同一图表再次打开直接展示，后台同范围数据更新直接替换。用户主动切换时间范围或口径时，保留原有连续过渡和交互反馈。
- 无可用内容时用匹配排版的骨架形状：文字与数值用短条，图标用对应大小的圆或圆角方块，曲线、柱和散点保留各自形态，不显示加载说明文字或转圈。错误和空数据仍显示真实提示。
- 首次等待时，柔和闪光沿骨架移动，周期 2.2 秒；曲线闪光不改变实际线宽。已展示过的图表若还需要等待，显示静态占位；有缓存的内容继续保留。
- 加载线采用平顺上升、末端轻微回落或收平的轮廓，并按当前图表尺寸缩放。线与圆环只合成着色一次，圆心从实际路径中扣除；首次过渡用单次描线的颜色插值，避免半透明叠层露出线头。
- 系统开启“减少动态效果”时，停止闪光和入场过渡，保留静态形状。
- 此规则管理展示动画，不修改任何网络缓存有效期，也不表示所有页面都已有同步展示缓存。
- 收益首页的立体热力图生成底图时，显式使用无交互的热力图：不创建长按个股预览或行业打开按钮。`ImageRenderer` 的独立环境不继承 `AppModel`；实际页面保留原有点击与预览，预览修饰器在缺少模型的独立渲染环境中仅绘制原内容。2026-09-15 真机崩溃日志确认，旧实现把预览依赖带入底图渲染，触发环境对象读取断言；本次修复只编译安装，不运行测试。

实现：[StandardLineChart.swift](../CatfolioIOS/CatfolioIOS/StandardLineChart.swift)。线宽见 [线宽.md](线宽.md)。

## 滚动时的展示更新

- 首页首次加载完成后，播放一次约 1.2 秒、从上到下的 Metal 波纹。等待组合、今日涨跌和资产图就绪，再留 0.5 秒让现有图表入场动画结束；空持仓、加载错误和开启“减少动态效果”时不播放。每次 App 启动最多一次，刷新、切换账户、返回首页不重播。波纹只处理当前可见区域的一张内存画面，不写入文件；触摸、开始滚动、离开页面、进入后台或窗口尺寸变化时立即结束并释放，空闲时不运行 Shader 或动画计时器。
- 首页原始滚动位置保存在独立状态中，资产卡片位移、前景卡片宽度、背景颜色和滚动条分别观察所需值。首页不再为每个滚动采样重新创建今日贡献和持仓视图；宽度与背景渐变到达端点后，也不再反复发布相同进度。
- 首页卡片的彩色边缘光晕已移除，包括浅色背景光晕和深色前景光晕；滚动时不再计算光晕强度，也不再创建对应的动画与延迟淡出任务。
- 首页卡片外侧的提前模糊带已移除，尚未被卡片覆盖的资产内容保持清晰。卡片本身保留原有液态玻璃，仅在圆角卡片内部采样背景，随展开进度过渡到不透明底色；保留宽度、圆角与底色渐变，吸附、惯性、下拉刷新和个股打开／退出行为不变。
- 各 Tab 的滚动方向累计值不参与界面观察，只有底栏确实需要收起或展开时才更新状态；持仓标题的玻璃样式只在跨过位置阈值时更新，不再向上发送每个滚动位置。
- 收益页热力图的持续漂移在拖动、惯性滚动、程序滚动、离开页面或 App 非活动时暂停，恢复后从暂停位置继续。展开／收起的交互过渡仍保留。
- 热力图底图等待页面停止滚动后再生成；证券数据、主题、尺寸、屏幕倍率、语言和已加载 Logo 未变时继续复用已生成图像。被取消的底图任务会取消后台模糊任务，并在模糊层之间检查取消状态。

这些调整减少界面更新与效果渲染开销，不改变金融计算或网络缓存有效期。按用户约定只做代码检查、编译安装，不运行测试或帧率采样，因此没有实测 FPS 结论。

实现：[PortfolioView.swift](../CatfolioIOS/CatfolioIOS/PortfolioView.swift)、[RootTabView.swift](../CatfolioIOS/CatfolioIOS/RootTabView.swift)、[ReturnsView.swift](../CatfolioIOS/CatfolioIOS/ReturnsView.swift)、[PerformanceHeatmapHero.swift](../CatfolioIOS/CatfolioIOS/PerformanceHeatmapHero.swift)。

## 个股页展示缓存

### 保存什么

`AppModel` 持有 `HoldingDetailCachedContent`，使数据不随详情 sheet 关闭而丢失。内容包括：

- 成交量分布及 52 周数据。
- 价格历史和已整理的走势图数据。
- 账户上下文、该详情的账户选择和已计算的已实现收益。
- 不同到期范围的期权墙快照。
- 按语言区分的研究卡片已知内容和可用状态，包括预测市场等。

### 范围与寿命

- 最多保留最近使用的 **24 个缓存条目**；超出后移除最久未使用的条目。
- 键包含投资组合来源、证券／报价币种、账户 ID 列表，避免不同来源或账户复用错误的持仓内容。
- 研究内容另按语言区分。
- 这层展示缓存只存在于当前 App 进程。进程结束、重新安装或条目被移除后，下一次仍需要从底层磁盘缓存恢复。
- 重置个人投资组合会移除个人来源的展示缓存。

### 打开和更新流程

1. 已有展示缓存时，直接用它创建页面，不先清空图表等待请求。
2. 没有展示缓存时，先尝试读底层磁盘缓存，包括已过期但仍可用的历史数据。
3. 再执行正常的数据加载，按各服务的有效期决定是否联网。
4. 自动更新期间保留已显示内容；成功后替换对应数据。
5. 走势图只有在历史、成本或账户范围变化时才重新整理；匹配的已整理结果可以复用。
6. 无任何可用缓存的首次加载仍需要加载状态。磁盘恢复也不等于同步、零耗时显示。
7. 持仓项长按的系统预览复用同一个股页与展示缓存，按相同有效期读取数据；从预览菜单打开详情后继续复用已取得的内容。

### 个股默认时间范围与顶部数字

- 每次新打开个股页或长按预览，价格图默认选择「一日（1D）」；缓存图表数据不会把默认范围改成一年或上次的选择。同一次页面内刷新行情保留当前选择。
- 顶部金额是每股报价，优先来自 `SecurityPriceHistory.latestAvailablePrice` 的带日期行情；历史未就绪时回退到持仓的 `quotePrice`。它不是持仓列表右侧的总市值。
- 「一日」未触摸图表时，涨跌幅使用该行情相对上一交易日收盘的日涨幅；没有历史行情时沿用已有日涨幅。图表准备完成不会再把它替换成一年涨幅或首末分钟价之间的涨幅。
- 手指选择一个历史点时，顶部显示该点价格与图表已计算的涨跌幅；一日以昨收为基准。手指离开恢复当前时间范围，区间测量仍按用户选择的两点计算。
- 主动切换到一周、一年等范围后，百分比显示所选区间的涨跌幅，因此不应和持仓页的「今日」或「累计持仓盈亏」直接等同。

实现：[VolumeProfileView.swift](../CatfolioIOS/CatfolioIOS/VolumeProfileView.swift) 的 `HoldingDetailPriceSection`、`SecurityPriceChart`、`SecurityPriceRangeData`；[Models.swift](../CatfolioIOS/CatfolioIOS/Models.swift) 的 `SecurityPriceHistory.latestMarketObservation`。

### 个股打开与关闭的动画

首页持仓行、今日贡献柱和热力图打开个股时，不再用系统的 `.navigationTransition(.zoom)`：iOS 26 上它的几何、时序、阴影和交叉淡化都不可控，结尾会把整页和行叠成重影。现在由 `SecurityDetailSnapshotTransition` 自己画：

- 打开：点击时记录来源的位置并截图；sheet 不带动画地出现但先隐藏；窗口顶层的一张卡片（页面底色）从来源位置长到 sheet 的位置，卡片里来源截图淡出、页面截图淡入，蒙层同步加深；落地后换成真实页面。价格区以下的卡片等这之后再构建并淡入。
- 关闭（✕）：页面截图放进卡片，sheet 立即关闭，卡片缩回来源**当前**的位置（排序变了也回到对的行），途中换成来源截图。
- 下拉关闭仍是系统 sheet 的滑出；没有登记来源的入口（研究、收益页等）保持普通 sheet。

蒙层深色 28% 黑、浅色 10% 黑。首页列表在惯性滚动或吸附时，一次触摸只用来停住列表，不会打开滑到手指下的那一行（`PortfolioHomeScrollController.touchCaughtMotion`）。

实现：`SecurityDetailTransition.swift`；`DesignSystem.swift` 的 `SecurityDetailZoomState`、`catfolioZoomSource`、`SecurityDetailBackdrop`；`VolumeProfileView.swift` 的 `showsLowerSections`。DEBUG 构建可用 `--demo-security-transition` 自动打开再关闭一次，便于录屏检查。

实现：[APIClient.swift](../CatfolioIOS/CatfolioIOS/APIClient.swift) 的 `cachedHoldingDetail`；[VolumeProfileView.swift](../CatfolioIOS/CatfolioIOS/VolumeProfileView.swift) 的 `HoldingDetailCachedContent`、`HoldingDetailContentView`、`SecurityPriceChart`。

## 个股页各模块

| 内容 | 加载入口 | 缓存与更新规则 | 保存／失败处理 |
|---|---|---|---|
| 分时行情 | 打开个股；点击顶部价格 | **5 分钟**。有效缓存直接使用，过期再获取 | 磁盘缓存；可回退旧分时数据 |
| 历史日线 | 打开个股；点击顶部价格 | **12 小时**，且缓存必须覆盖请求日期。过期时优先增量补齐；强制刷新走重新获取流程 | 磁盘缓存；读取失败时尽量保留旧历史 |
| 成交量分布／52 周区间 | 打开个股；点击顶部价格 | 底层日 OHLCV 缓存 **24 小时** | 磁盘保存原始 bars，展示缓存保留计算结果；更新失败可回退旧 bars |
| 期权墙 | 打开个股；切换到期范围；价格刷新联动；失败重试 | 按**纽约日历日期**判断当天缓存，7D／30D／90D 分开保存；不是交易所 OI 数据日期，也不是滚动 24 小时 | 磁盘快照及展示缓存；失败保留旧墙并显示提示 |
| 预测市场 | 显示卡片；卡片刷新按钮 | **15 分钟**，按证券、公司名称及语言区分 | 磁盘及展示缓存；先展示已有市场，更新时不切回占位图；失败可返回旧结果 |
| 分析师一致预期 | 个股出现时只读缓存；无结果时展开卡片才请求 | 有效内容**没有固定自动过期时间**；手动刷新才重新获取 | 持久化快照，App 重启后可用 |
| 盈利历史 | 个股出现时只读缓存；展开卡片时检查 | **24 小时**；同次访问成功加载后，不因重复折叠／展开反复加载；提供手动刷新 | 有效旧内容可继续展示；更新失败保留已有图表 |
| 内部人士交易 | 点击进入详情；详情刷新 | **12 小时**；过期优先读取最新 25 条并与旧记录合并，必要时补取完整范围 | 持久化快照；失败返回旧缓存 |
| 财务报表 | 点击进入财务页；下拉／重新读取 | **24 小时**；过期先请求更新 | SEC 失败时优先使用 7 天内旧报表，再尝试其他来源；最终仍可回退更旧缓存 |
| AI 关键变化 | 恢复保存结果；点击生成／重新分析 | 完成结果没有固定自动过期时间；同证券、同语言的运行中任务不重复创建 | 持久保存成功结果，失败不覆盖有效旧结果 |
| 管理层兑现情况 | 进入恢复资料；点击分析／刷新 | 没有固定有效期；非刷新分析可复用已下载资料 | 本地保存资料与报告，更新成功后替换 |
| “为什么涨／跌了”短解读 | 点击顶部解释按钮 | 同行情上下文、同语言 **15 分钟内**复用；没有运行中的重复请求 | **仅内存缓存**，App 进程结束后需要重新生成 |

补充：

- 基金研究卡片是否出现取决于是否有实际可用内容；部分基金卡片初始只恢复缓存，不自动发起完整研究请求。
- 预测市场有内容的旧缓存可以继续显示；空结果缓存过期后，不应一直压制后续新内容。
- 分析师的持久快照规则优先于其备用服务内部的短时缓存，不能把备用服务的期限当作页面的自动刷新周期。
- 本地持仓、账户、已实现收益等读取和计算，不等于同步一次券商账户。

## 持仓、收益与交易记录

各个 Tab 分别持有自己的 `NavigationStack`，大标题、收起状态和返回路径由本页导航栏管理。标题由收益、研究、设置页面各自声明，首页仍使用原有资产摘要。Tab 切换不再修改共享导航栏的标题，也不为修复标题而重建页面或清空数据缓存。`NavigationBarScrollAnchor` 在页面出现前绑定本页滚动区域，只作用于最近导航栈中的页面控制器。

Tab 切换的选择震动由始终挂载的 `RootTabView` 统一监听，不能放在随切换出现／消失的各页底栏上。切换到其他 Tab 时触发一次，重复点击当前 Tab 不触发，并遵守 `catfolio.haptics` 开关。

| 页面／数据 | 当前规则 |
|---|---|
| 持仓首页 | 首次缺数据时调用加载；先显示本地持仓，再更新报价与历史图。普通返回且已有 overview 时，不仅因返回就再次整页刷新。下拉触发刷新流程 |
| 持仓报价 | 持仓刷新流程中按证券和币种合并请求，更新结果保存到本地；不是一个统一“整页缓存多少分钟”的规则 |
| 今日贡献／持仓热力图 | 优先已有持仓涨跌数据，缺失部分补读行情。数据签名未变时避免重复处理；底层历史遵循日线缓存规则 |
| 收益对比图 | 按数据来源和账户范围保存计算结果。指纹包含日期、语言、基准、交易、持仓等；相同时复用，变化时保留旧结果并重新计算 |
| 收益详情进入 | 缺少收益对比或分析数据时才补加载，不因每次进入而把两类请求全部重跑 |
| 收益估值数据 | 基本面缓存 **12 小时**；失败后 **5 分钟内**避免重复请求 |
| 收入来源／水下分析 | 每次加载当前仍会先清空该图状态，再读本地历史，随后按服务缓存规则更新。**仍可能出现短暂加载状态** |
| 交易记录 | 先读本地账本，再同步符合条件的 Trading 212 账户。停留期间每 **65 秒**尝试同步一次；离开后停止 |
| Trading 212 同步 | 使用持久化分页检查点、续传位置和重试时间。65 秒是页面尝试同步的间隔，不保证每个数据接口都执行请求；同步也不只是读本地界面缓存 |
| 公开投资者组合 | 先显示保存的组合；同一天 **5 分钟内**复用，超过后在刷新流程中检查更新；历史价格另受日线缓存管理 |
| 汇率 | 保存本地结果；当前进程的更新尝试间隔至少 **30 分钟**，底层汇率日线仍遵循历史缓存规则 |
| 股息预测日期 | **12 小时内存缓存**，当前进程结束后不保留这层缓存 |

收益对比的“每天变化”由输入指纹中的日期触发，不是常驻的午夜刷新任务。手动调用收益刷新时，如果指纹仍相同，仍可能直接返回已保存结果。

## 刷新入口的实际范围

| 操作 | 影响范围 |
|---|---|
| 点击个股顶部价格 | 强制更新价格走势、成交量分布，并通知期权墙更新；不刷新所有研究卡片 |
| 预测市场、分析师、盈利历史等卡片刷新 | 仅更新各自模块 |
| 财务页面下拉／重新读取 | 请求更新财务数据，保留既有失败回退规则 |
| 持仓首页下拉 | 执行持仓页面刷新流程；不等同于所有券商、研究模块都强制同步 |
| 收益页面下拉 | 执行对应收益刷新；收入来源／水下分析只触发自己的历史任务；有效缓存仍可能复用 |
| 研究市场页下拉 | 重新执行市场历史加载，但底层有效日线缓存仍然生效 |
| 重新打开个股 | 复用展示缓存并检查服务缓存；不是一次全模块强制刷新 |
| App 回到前台 | App 级场景回调明确刷新云偏好；不代表自动强刷全部行情 |

强制刷新也必须遵守服务的并发和限流规则。例如期权服务遇到 Yahoo 429 后，会进入至少 5 分钟、最多 24 小时的冷却，具体参考返回的重试时间，不会因重复点击而绕过。

## 尚未统一的部分

- “有缓存就立即显示、后台更新不清空”不是全 App 的统一保证。
- 个股展示缓存是内存缓存；冷启动的磁盘恢复仍是异步过程。
- 收入来源、水下分析会先重置图表状态；管理层资料恢复、AI 报告恢复和财务页仍有自己的加载流程。
- 分析师长期复用、期权墙按纽约日期、行情按时长、收益对比按输入指纹，是不同策略，不能混写成统一期限。
- 多数模块保留失败前的有效内容，但各自的回退、空结果和错误提示逻辑不同。

本次更新了图表首次动画和加载占位规则，未运行测试；实际视觉效果由用户验证。后续若调整加载策略，需要同时更新本文中的触发时机、有效期、保存位置和失败行为。
